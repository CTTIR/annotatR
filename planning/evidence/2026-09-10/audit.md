Audit of annotatR 0.1.0, 2026-09-10, revision `f69bf201f651c845ab496f76e25638bc919d4b13`.

25 defects were reproduced: 10 high priority (P1) and 15 medium priority (P2). The highest risks are assigning annotations to the wrong image, losing session work, and silently changing masks or spectra. Repository files were not changed.

P1 means address before relying on the affected workflow; P2 means a reproducible defect in a narrower supported configuration. These priorities describe practical impact, not CVSS security scores.

Validation and scope:

- Existing suite: 287 test cases, 710 passing assertions, zero failures/errors/warnings, one skipped test. The skip was the cuvis.r-absent error-path test because cuvis.r is installed. [Full test log](tests.log).
- Built a source package from the clean tracked revision. `R CMD check --no-manual --no-tests --ignore-vignettes`, with `_R_CHECK_FORCE_SUGGESTS_=false`, completed with two NOTEs: `.zenodo.json` included in the package and `CITATION.cff` in a non-standard location. Examples passed. Tests were run separately; manual and vignette builds were not checked. [Check log](package-check.log).

1. **P1 — Restoring an app save does not restore readable image data.** [mod_session.R:16](../../../inst/shiny/annotatR/modules/mod_session.R), [app.R:14](../../../inst/shiny/annotatR/app.R). Saving removes `image$handle`. Loading an existing project returns it without reopening its source, while tile backends require the handle. After saving a lightweight example project, reloading and clearing the process cache, `at_tile()` returns length zero and `at_tile_source()` has no image URI. Resume therefore loses the image display and usable pixel access. Reopen stripped handles from their source/backend before use, preserving reader options needed for nonstandard cubes. Add a fresh-process app-save/resume test.

2. **P1 — Shift+Enter can save the current image under the next queue entry.** [app.R:140](../../../inst/shiny/annotatR/app.R), [mod_session.R:29](../../../inst/shiny/annotatR/modules/mod_session.R). The shortcut changes `trigger_save` and advances the cursor before the save observer runs. With autosave disabled, drawing on image 1 and pressing Shift+Enter left image 1 marked complete with no saved project, while slot 2 contained image 1's project. Serialize the current project/index synchronously before advancing; do not let a deferred save read a mutable cursor. Test both autosave settings and the final queue entry.

3. **P1 — Undo history crosses image boundaries.** [app.R:112](../../../inst/shiny/annotatR/app.R), [app.R:161](../../../inst/shiny/annotatR/app.R). History contains complete projects and is retained during navigation. Draw/save on image 1, navigate to image 2, then Undo: the cursor remains 2 but the live project and image become image 1. A subsequent save assigns that project to image 2. Keep history per image/session or clear it on every image/session transition, and validate project identity before saving.

4. **P1 — Loading a folder at cursor 1 retains the previous image.** [mod_data.R:44](../../../inst/shiny/annotatR/modules/mod_data.R), [app.R:161](../../../inst/shiny/annotatR/app.R). Folder load replaces the session and sets `cursor <- 1L`; image materialization observes only cursor changes. When already at 1, the queue updates but the old project stays active. Reproduction showed manifest `new.tif` alongside live image `image_01.png`. Observe session identity as well as cursor, or explicitly materialize/reset state when replacing a session. Include one-image queues in the regression test.

5. **P1 — The rectangle fast path fills some triangles as rectangles.** [perf.R:64](../../../R/perf.R). Two distinct x and y coordinates do not establish a rectangle. The triangle `(0,0), (5,0), (5,5)` satisfies that condition. Its mask contains 25 pixels when rasterized alone, but 13 for the same triangle after adding an unrelated ROI and selecting the batch rasterizer. Extraction also uses the faulty fast path. Require the four rectangle corners and axis-aligned edges, and compare this case against the general rasterizer.

6. **P1 — GeoJSON and CSV round trips apply pyramid scaling twice.** [io-geojson.R:120](../../../R/io-geojson.R), [io-csv.R:30](../../../R/io-csv.R). Coordinates are transformed to the export level (GeoJSON) or level zero (CSV), but the serialized `level` remains the ROI's original level. Import trusts that field and later rescales already transformed coordinates. A level-1 ROI with level-zero area 36 returned with area 144 through either format. Store the coordinate level actually written. Test original/export levels independently, including anisotropic pyramids.

7. **P1 — ROI ID collision repair can mint another existing ID after restart.** [class-project.R:197](../../../R/class-project.R), [class-layer.R:114](../../../R/class-layer.R). The process-local ID counter restarts at zero, and each collision check only tries one replacement. Loading four saved ROIs in a fresh counter state and adding another produces IDs `1,2,3,4,3`; `at_validate()` then fails. Deletion/editing by ID can affect multiple annotations. Generate until the candidate is unique across the complete project, including layer insertion and imports.

8. **P1 — Images sharing a basename overwrite each other's exports and app project files.** [batch.R:128](../../../R/batch.R), [mod_session.R:30](../../../inst/shiny/annotatR/modules/mod_session.R), [mod_export.R:39](../../../inst/shiny/annotatR/modules/mod_export.R). Session names discard directories and file extensions, and writers use those names as unique output identifiers. Two `same.tif` files in different directories yielded two successful export receipts but only one file containing the second image's label with `overwrite=TRUE`; the app always enables overwrite. Assign stable unique queue keys to filenames and preflight collisions. Preserve display names separately.

9. **P1 — Tile caching can return pixels from another file.** [perf.R:24](../../../R/perf.R), [backend.R:171](../../../R/backend.R). The cache key uses the original source string rather than canonical file/handle identity. Reading relative `same.tif` paths from two directories creates identical keys. Reproduction returned the first image's all-zero tile for a second image whose actual handle contained all 255s. Canonicalize sources at read time and include a handle/content identity so different reads/options or replaced files cannot share stale pixels.

10. **P1 — ENVI binary headers are interpreted as image samples.** [backend-envi.R:84](../../../R/backend-envi.R), [backend-envi.R:97](../../../R/backend-envi.R). The parser ignores `header offset`, and the reader starts at byte zero. A four-byte header sentinel `999` followed by four valid float samples became the first pixel and displaced a real sample. Parse and validate the offset, then seek before decoding. ENVI explicitly requires skipping this number of bytes. [Vendor format documentation](https://www.nv5geospatialsoftware.com/docs/enviheaderfiles.html).

11. **P2 — Undo/Redo changes are not marked dirty or autosaved.** [app.R:112](../../../inst/shiny/annotatR/app.R), [mod_session.R:52](../../../inst/shiny/annotatR/modules/mod_session.R). History handlers replace the project without setting `rv$saved <- "unsaved"`; autosave requires that flag. After drawing and autosaving one ROI, Undo left zero live ROIs, one saved ROI, and indicator `saved`. Route history mutations through the same dirty/save mechanism as drawing. This is separate from history crossing images.

12. **P2 — Navigation discards unsaved annotations when autosave is disabled.** [app.R:161](../../../inst/shiny/annotatR/app.R), [mod_queue.R:27](../../../inst/shiny/annotatR/modules/mod_queue.R). The live project is copied into the session only by saving. Next then Previous replaces it with the old/unmaterialized project without retaining edits. Reproduction changed the ROI count from one to zero. Preserve the current project in the in-memory session before navigation independently of disk autosave; track dirty state per image.

13. **P2 — Truncated ENVI and NPY payloads are silently recycled into complete arrays.** [backend-envi.R:97](../../../R/backend-envi.R), [io-npy.R:96](../../../R/io-npy.R). Neither reader verifies the number of decoded elements. A declared four-element NPY containing two integers returns `1,2,1,2`; ENVI similarly repeats two available samples into four pixels. Reject short payloads and malformed dimensions before constructing matrices/arrays, using double arithmetic for expected byte counts.

14. **P2 — Valid numeric options are rejected, and mask connectivity is unused.** [utils-check.R:181](../../../R/utils-check.R), [mask-io.R:164](../../../R/mask-io.R), [mask-io.R:186](../../../R/mask-io.R). `.check_choice()` requires character input even for integer choices. `bits=8L` and `connectivity=4L` error while listing those same values as allowed. The default vectors bypass the check, hiding the problem. Support numeric choices and pass connectivity into polygonization; it is currently assigned but never used. Test explicit defaults, alternatives, and diagonal components.

15. **P2 — Integer-coordinate point ROIs disappear from extraction.** [extract.R:24](../../../R/extract.R). For a point at `(5,5)`, the bounding range becomes `6:5`, so extraction skips it even though `at_mask()` covers one pixel. Use the point rasterizer's pixel-index rule for point bounds and handle zero-width/height geometries consistently. The reproduction produced one mask pixel and zero extraction rows.

16. **P2 — Boolean ROI operations combine different pyramid coordinate spaces.** [geometry.R:179](../../../R/geometry.R), [geometry.R:204](../../../R/geometry.R). Union/intersection/difference/symmetric difference use raw coordinates and inherit the first ROI's level. Subtracting a level-1 `0..5` square from the physically identical level-0 `0..10` square yields area 75 instead of an empty result. Normalize levels with image dimensions or reject mixed levels explicitly. Do not silently infer arbitrary pyramid ratios.

17. **P2 — A background code matching a foreground code erases annotations.** [mask.R:237](../../../R/mask.R), [mask.R:256](../../../R/mask.R). `background=1L` is accepted, but binary foreground is also 1, and conversion compares everything against the background. A nine-pixel ROI consequently yields an empty binary mask. Labelled/multiclass collisions also make overlap handling ambiguous. Reject collisions before rasterization or separate occupancy from encoded values.

18. **P2 — Image downsampling misaligns plotted ROI overlays.** [plot.R:31](../../../R/plot.R), [plot.R:204](../../../R/plot.R). Image plotting replaces sampled coordinates with `1..n`, whereas overlays retain level-zero coordinates. A 2048-square image plots across x=1..1024, but its ROI remains at x=1800..1900, outside the displayed image. Preserve the sampled image coordinates and pyramid transform, including pixel-center offsets, in plot data.

19. **P2 — RDS mask import loses the embedded label legend.** [mask-io.R:167](../../../R/mask-io.R). `.read_mask_matrix()` supplies the saved mask object, but `at_read_mask()` only consults an explicit legend or JSON sidecar. RDS exports intentionally have no sidecar. A saved `tumour` mask imports as label `"1"`. Recover the embedded legend (and relevant level metadata) before falling back to external sidecars.

20. **P2 — Bitfield mask statistics exclude overlapping memberships.** [mask.R:673](../../../R/mask.R). The bitwise-OR rasterizer's legend correctly counts membership using `bitwAnd`, but statistics use exact equality. Two 36-pixel classes overlapping by four pixels have legend counts `36,36` and reported stats `32,32`. Bounding boxes, centroids, and previews can likewise omit composite-code pixels. Preserve encoding/overlap metadata and use membership-aware calculations consistently; do not treat ordinary multiclass masks as bitfields.

21. **P2 — Per-ROI mask export loses the actual pyramid transform.** [mask-io.R:264](../../../R/mask-io.R). Export passes a standalone ROI and dimensions to `at_mask()`, removing the image metadata needed for non-power-of-two scaling. On a pyramid downsampling x by 4 and y by 2, the project mask covers 72 pixels but `at_write_masks(per="roi")` writes 36. Transform using the project image before rasterization or select each ROI within a project retaining that metadata.

22. **P2 — Names can escape the requested mask export directory.** [mask-io.R:242](../../../R/mask-io.R), [mask-io.R:272](../../../R/mask-io.R). Names and labels are interpolated directly into paths. A project named `../escaped`, exported with `per="project"`, writes `escaped.tif` one directory above `dir`. This is an output-path boundary defect, not evidence of remote code execution. Map names to safe filename components and verify resolved outputs stay under the destination. Keep original names in manifests.

23. **P2 — Default session saves ignore `overwrite=FALSE`.** [io-project.R:75](../../../R/io-project.R). The overwrite check runs only for an explicit path; the default `_session.rds` path is resolved later. Two default saves with overwrite disabled silently replace the first file. Resolve the effective path before checking; have the app explicitly request overwriting for autosave. Distinct sessions also need distinct default output locations if they should not share `_session.rds`.

24. **P2 — The canvas treats polygon holes as filled, selectable regions.** [atcanvas.js:56](../../../inst/htmlwidgets/atcanvas.js), [atcanvas.js:123](../../../inst/htmlwidgets/atcanvas.js). Rendering and hit-testing use only the first ring. Clicking the empty center of a donut emits an erase event for the donut, and display fills that hole. MultiPolygon rendering/hit-testing is also absent despite supported imported/derived geometries. Draw all rings with an appropriate fill rule and test exterior membership minus holes, including multipolygons. The Node reproduction exercises hole erasure.

25. **P2 — A second canvas instance replaces the first instance's proxy handlers.** [atcanvas.js:249](../../../inst/htmlwidgets/atcanvas.js). Each widget registers the same global Shiny custom message names. Shiny replaces existing handlers of that name; the new handler then ignores IDs other than its own. After mounting widgets A and B, setting A to the point tool via a proxy has no effect: its click still emits an erase event. Register one dispatcher with an instance registry, and clean up on widget disposal. The harness behavior matches the installed Shiny implementation.

Additional review observations, separate from the 25 reproduced defects:

- The documented lazy-image contract is not implemented by the built-in backends: [backend-envi.R:123](../../../R/backend-envi.R), [backend-tiff.R:60](../../../R/backend-tiff.R), and [backend-raster.R:18](../../../R/backend-raster.R) eagerly load complete arrays. Reading whole-slide data can exhaust memory before tile access. Session projects also retain these arrays. The existing extraction-memory test constructs a large array before measuring and therefore does not verify lazy file reads. Large real WSI memory behavior was not load-tested.
- [widget-canvas.R:45](../../../R/widget-canvas.R) relies on magick for all embedded image display and suppresses image-generation errors to NULL. The launcher does not require magick; a package configuration sufficient for TIFF reading can still show an empty canvas. `max_dim` selects a pyramid level but does not shrink a non-pyramidal embedded image.
- The existing suite mostly checks modules independently; its full-app test constructs an app object without running the server interactions that exposed findings 2–4 and 11–12. Add those interaction regressions first, followed by independent file-format fixtures and optimized-versus-general rasterizer checks.
- The workflow files delegate most checks to shared workflows; lint is nonblocking and the configured coverage floor is zero. No runtime security guarantee follows from the passing local tests. No credential-like private key/cloud-token patterns were found in the targeted source/config scan; this was not a full history or dependency-vulnerability scan.

Suggested order of work: fix project/index identity and persistence (1–4, 7–8, 11–12), then mask/coordinate fidelity (5–6, 15–21), then readers and output handling (9–10, 13–14, 22–23), then widget geometry/routing (24–25). Add a failing regression for each confirmed case before implementing its fix.
